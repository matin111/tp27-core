تست واقعی Source IP در Lab ایزوله

این آموزش برای کاربر مبتدی طراحی شده است. دو شبکه مجازی فقط داخل همان VPS ساخته می‌شود و هیچ Default Route به آن‌ها داده نمی‌شود. مقصد تست خصوصی است و Source آزمایشی از محدوده مستندسازی TEST-NET استفاده می‌کند.

محدودیت مهم: این تست فقط ثابت می‌کند Kernel/Raw Socket سرور می‌تواند Packet با Source متفاوت را داخل Lab بسازد و تحویل دهد. این تست ثابت نمی‌کند دیتاسنتر اجازه خروج چنین ترافیکی به اینترنت را می‌دهد. برای Provider همچنان نتیجه باید UNKNOWN بماند مگر مدرک مستقل وجود داشته باشد.
1

ساخت Lab ایزوله

کل بلوک را Copy کن و روی همان VPS با دسترسی root اجرا کن.

set -e
ip netns del tp27-src 2>/dev/null || true
ip netns del tp27-dst 2>/dev/null || true
ip netns add tp27-src
ip netns add tp27-dst
ip link add tp27-veth-a type veth peer name tp27-veth-b
ip link set tp27-veth-a netns tp27-src
ip link set tp27-veth-b netns tp27-dst
ip -n tp27-src link set lo up
ip -n tp27-dst link set lo up
ip -n tp27-src addr add 10.200.0.1/24 dev tp27-veth-a
ip -n tp27-dst addr add 10.200.0.2/24 dev tp27-veth-b
ip -n tp27-src link set tp27-veth-a up
ip -n tp27-dst link set tp27-veth-b up

echo "LAB_CREATED=YES"
ip -n tp27-src route
ip -n tp27-dst route

در خروجی نباید Default Route ببینی. فقط Route شبکه 10.200.0.0/24 وجود دارد.

2

Receiver را اجرا کن

یک SSH/Terminal دوم به همان VPS باز کن و این بلوک را اجرا کن. Terminal منتظر Packet می‌ماند.

ip netns exec tp27-dst python3 - <<'PY'
import socket
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.bind(("10.200.0.2", 49000))
s.settimeout(20)
try:
    data, addr = s.recvfrom(2048)
    print("LAB_PACKET_RECEIVED=YES")
    print("SOURCE_IP=" + addr[0])
    print("SOURCE_PORT=" + str(addr[1]))
    print("PAYLOAD=" + data.decode("utf-8", "replace"))
except TimeoutError:
    print("LAB_PACKET_RECEIVED=NO")
finally:
    s.close()
PY
3

Sender آزمایشی را اجرا کن

به Terminal اول برگرد. این Sender یک IPv4/UDP Packet داخل همان Namespace می‌سازد. Source برابر 198.51.100.77 است؛ این Prefix برای مستندسازی رزرو شده است.

ip netns exec tp27-src python3 - <<'PY'
import socket, struct

SRC = "198.51.100.77"
DST = "10.200.0.2"
SPORT = 40000
DPORT = 49000
PAYLOAD = b"TP27-LAB-SOURCE-TEST"

def checksum(data):
    if len(data) % 2:
        data += b"\x00"
    total = sum(struct.unpack("!%dH" % (len(data)//2), data))
    total = (total & 0xffff) + (total >> 16)
    total += total >> 16
    return (~total) & 0xffff

udp = struct.pack("!HHHH", SPORT, DPORT, 8 + len(PAYLOAD), 0) + PAYLOAD
ver_ihl = 0x45
total_len = 20 + len(udp)
ip0 = struct.pack(
    "!BBHHHBBH4s4s",
    ver_ihl, 0, total_len, 0x2727, 0, 64, socket.IPPROTO_UDP, 0,
    socket.inet_aton(SRC), socket.inet_aton(DST),
)
ip_sum = checksum(ip0)
ip_header = struct.pack(
    "!BBHHHBBH4s4s",
    ver_ihl, 0, total_len, 0x2727, 0, 64, socket.IPPROTO_UDP, ip_sum,
    socket.inet_aton(SRC), socket.inet_aton(DST),
)

s = socket.socket(socket.AF_INET, socket.SOCK_RAW, socket.IPPROTO_RAW)
s.setsockopt(socket.IPPROTO_IP, socket.IP_HDRINCL, 1)
s.sendto(ip_header + udp, (DST, 0))
s.close()
print("LAB_PACKET_SENT=YES")
print("CLAIMED_SOURCE=" + SRC)
PY
4

نتیجه را بخوان

اگر Terminal دوم این خروجی را نشان داد:

LAB_PACKET_RECEIVED=YES
SOURCE_IP=198.51.100.77
PAYLOAD=TP27-LAB-SOURCE-TEST
LAB_RAW_SOURCE=PASS
یعنی Kernel و Raw Socket روی این VPS در محیط ایزوله توانسته‌اند Packet با Source متفاوت بسازند و Receiver همان Source را دیده است. نتیجه Provider همچنان UNKNOWN است.

اگر Receiver Timeout شد یا Sender خطای Permission داد، نتیجه Lab را FAIL در نظر بگیر و ابتدا CAP_NET_RAW / root / Kernel را بررسی کن.

5

پاک‌سازی

ip netns del tp27-src 2>/dev/null || true
ip netns del tp27-dst 2>/dev/null || true
echo "LAB_CLEANUP=OK"

این کار هر دو Namespace و vethهای داخل Lab را حذف می‌کند.

برای انتخاب VPS چه نتیجه‌ای خوب است؟

  • Host Checker = READY
  • Lab Raw Source = PASS
  • Provider = UNKNOWN یعنی هنوز درباره فیلتر بالادستی ادعای قطعی نداریم.
  • اگر Provider مستندات رسمی درباره Source Validation / Anti-Spoof دارد، همان مدرک را جداگانه بررسی کن.
